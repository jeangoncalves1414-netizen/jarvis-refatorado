# Real FSRS scheduling, review undo, unified XP and study dashboard for Jarvis Estudos

The change implements Phases 1 and 2 of the study-system review plus items 6.5, 6.8 and 9. The `language` chat mode now gets its own CEFR prompt and only the four `language_*` tools. The hand-rolled scheduler is replaced by py-fsrs 6.3.2 behind the existing `app/storage/tutor/fsrs.py` API, with learning steps, a 365-day interval cap, pre-review retrievability and lazy migration of stored cards. Both decks write an append-only review log that supports exact undo, and both share one XP/streak service. On the frontend this adds a "Hoje" dashboard, SVG progress charts, keyboard shortcuts, undo, vocabulary delete through `ConfirmDialog` and a deadline-based Pomodoro that awards XP once. It also fixes the field-name, speech-language, queue-skipping and listener-leak bugs.

Watch for: keyboard grading has no in-flight guard, so a fast double press or key auto-repeat reviews the same card twice (confirmed); a review entry whose card was deleted or changed blocks undo for every older review in that deck (confirmed); language undo leaves `stats.vocab_mastered` unrestored (confirmed); two new catalog entries promise reversibility that no feature provides (confirmed). All are minor.

**Verdict**: APPROVED

## High-level view

Language mode now works like tutor mode. The orchestrator builds `build_language_system(...)` from the language store with no memory, persona or situational context. The registry treats `STUDY_MODES = {tutor, language}` as closed tool sets with no MCP tools, no Groq core list and no video routing. `allowed_tool_names` still produces the declarations, so the two lists stay equal. Two of the eight new low-risk `TOOL_CATALOG` entries describe undo paths that the app doesn't have.

The scheduler maps grades 0-3 to py-fsrs Rating 1-4, with steps of 1 and 10 minutes, `maximum_interval=365` and no fuzzing. Migration only adds keys, sets due to local midnight and checks review cards by local day, so migrated cards keep their due day. Grades are validated before card lookup, and the APIs return 400 `invalid_grade`.

Undo restores the raw before snapshot, including keys that were absent, revokes XP on the review's original day and appends its own log entry. It always targets the newest active review, so one review that can't be undone (card deleted or changed afterwards) blocks every older review in that deck.

XP, goal and streak live in one cached `StudyXP` per path, shared by both stores and the study API. Streak is computed on read from days that have XP, and legacy totals are imported once per source.

The review queues now reset to index 0 on refresh, which fixes the skipped cards. Neither the new keyboard shortcuts nor the buttons block a second grade while the first request is still in flight. The Pomodoro fires `onComplete` once per cycle, and the smoke test asserts a single `/api/study/pomodoro` POST.

1. **Double grading from keyboard** — `useReviewShortcuts` ignores `event.repeat`, and `reviewCard`/`reviewVocab` have no in-flight guard, so one card can be reviewed twice with double XP and two log entries. Skip repeated keydown events and ignore grade calls while a review request is pending.
2. **Undo blocked by an un-undoable entry** — `last_active_review()` keeps returning a review whose card was deleted or changed, so every later undo returns 409 and older reviews can never be undone. When the newest entry can't be undone, mark it skipped (for example, append an `undo_skipped` entry) or let undo move on to the next older review.
3. **Language undo leaves `vocab_mastered` stale** — `LanguageStore.undo_last_review` restores the card but doesn't recompute `stats.vocab_mastered` (the tutor path does call `_refresh_flashcard_stats`). Call `self._count_mastered()` after the restore.
4. **Reversibility claims with no feature behind them** — the `tutor_add_flashcard` entry says "exclua o flashcard criado" and the `language_add_weak_phoneme` entry says "remova o fonema", but the app can't delete flashcards or remove phonemes. Mark both `reversible=False` with accurate text, or add the delete/remove features.

### Catalog reversibility for study tools

The catalog entries feed `action_proposals.py`, which shows a reversibility sentence to the user. Two entries describe undo paths that don't exist (confirmed):

```python
"tutor_add_flashcard": ToolMetadata(..., reversible=True, ...,
    reversibility="Reversível: exclua o flashcard criado.")      # no flashcard delete anywhere
"language_add_weak_phoneme": ToolMetadata(..., reversible=True, ...,
    reversibility="Reversível: remova o fonema da lista ...")     # no remove_weak_phoneme
```

`undo_available` also requires an `undo_payload`, so the UI won't show a broken undo button. Only the text is wrong.

### Review log and undo

```
review_flashcard / review_vocabulary
  before = snapshot(raw card) -> normalize in place -> apply_review -> after = snapshot
  save progress.json -> xp.add(10) -> review_log.append({..., before, after, xp})

undo_last_review
  entry = newest review not targeted by an undo
  card missing        -> 409 card_not_found
  snapshot != after   -> 409 stale
  restore(before) -> save -> xp.revoke(entry.xp, entry.local_date) -> append {type: undo}
```

The undo target is always the newest active review (confirmed, `review_log.py` `last_active_review`). Suppose the user reviews word A, deletes it, then reviews word B. The first undo restores B. Every undo after that hits A, returns 409 `card_not_found` and never reaches older reviews. A `stale` entry blocks undo the same way. The plan accepted the 409 for deleted cards but not the permanent block on older reviews.

`LanguageStore.undo_last_review` restores the card and saves, but it doesn't recompute `stats.vocab_mastered` (confirmed). If a review pushed a card past the mastered threshold, undoing it leaves the counter one too high until another review recalculates it. The tutor path calls `_refresh_flashcard_stats()` and doesn't have this gap.

### Double grading from the review shortcuts

`useReviewShortcuts` doesn't filter `event.repeat`, and the grade callback has no pending flag (confirmed):

```ts
// useStudy.reviewCard: card comes from the closure; nothing changes until the fetch resolves
const card = dueCards[studyCardIndex]
const response = await fetch('/api/tutor/flashcards/review', ...)
```

A second keypress before the response finds the same card, because no state has changed yet, so it posts the same `card_id` again. The second review runs on the post-review state and awards another 10 XP. `useLanguage.reviewVocab` works the same way. Undo can recover, which keeps this minor. The grade buttons already had this race at the base commit, but holding a key now triggers it easily.
